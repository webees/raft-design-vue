# Architecture

**English** | [简体中文](../zh/architecture.md)

## Repository layout

```
packages/ui/          Vue component library, tokens, themes, compiled styles
apps/docs/            Rsbuild documentation and component gallery
tooling/upstream/     Upstream sync, lockfile, drift report, parity audit
tests/                Cross-package consumer smoke tests
design/               Synced upstream Markdown (read-only, never translated)
```

The workspace is a Bun monorepo. Every package declares its own dependencies;
the root only owns scripts, shared TypeScript settings and the lockfile.

## Build pipeline

`bun run build` runs three stages in order:

1. **Tokens** — `tokens.json` + `themes.json` become `foundation.css`,
   `themes.css` and the Tailwind `@theme` block.
2. **Library** — Rslib (Rsbuild) bundles ESM, Vue SFCs compile through
   `@rsbuild/plugin-vue`, `vue-tsc` emits declarations, then
   `scripts/normalize-dts.mjs` flattens Vue's declaration helpers.
3. **Docs** — Rsbuild renders `design/` Markdown and the component gallery.

Only step 2 emits the published package. Docs and tests consume the same
source that ships, so a green docs build is a real integration check.

## Vue auto-import

`unplugin-auto-import` is wired into Rslib, Vitest and the docs builder with
the `vue` preset:

```ts
AutoImport({ imports: ["vue"], dts: "src/auto-imports.d.ts" });
```

SFCs and TypeScript modules therefore use `ref`, `computed`, `useAttrs`,
`watch`, lifecycle hooks and the other Vue runtime APIs without an import.
Types that appear in public props stay explicit
(`import type { Ref, VNode } from "vue"`) because declaration emit needs
module-level symbols.

The generated `src/auto-imports.d.ts` is committed and excluded from Biome.
Never edit it by hand; it is regenerated by every build and test run.

Every file under `packages/ui/src` is compiled by that preset, so adding a
runtime import back is a lint smell rather than a requirement.

## Linting and formatting

Biome replaces ESLint and Prettier:

```bash
bun run lint      # biome check .
bun run format    # biome check --write .
```

`biome.json` pins the same style the repository already used (100 columns,
2-space indent, double quotes, semicolons, trailing commas) and excludes
generated artifacts, `design/`, synced CSS and the Tailwind entry.

Two Vue-specific exceptions are deliberate:

- Template usage is invisible to script-level analysis, so
  `noUnusedVariables`, `noUnusedImports` and `useImportType` are off for
  `.vue` files. `vue-tsc` is the authority for Vue code.
- Opinionated rules that fight the upstream recipes (`noImportantStyles`,
  `noDescendingSpecificity`, `noFocusedTests` on `fit()` helpers) are off.

## Quality gates

`bun run verify` is the only required command:

```
check:parity → check:audit → check:docs-links → lint → typecheck
→ check:api → check:props → test → build → check:consumer-types
```

CI runs the same chain on Node 22 with Bun, plus coverage. The release
workflow runs the same chain and only publishes when the `NPM_TOKEN` secret is
set; without it the run still versions and opens the release PR but skips the
npm publish and reports a warning instead of failing.

## TypeScript

The root config enables `strict`, `exactOptionalPropertyTypes`,
`noUncheckedIndexedAccess` and `verbatimModuleSyntax`. `vue-tsc` checks SFCs;
`tsc` checks tooling and tests. Public types are snapshotted by `check:api`
(960 exports) and props by `check:props`.
